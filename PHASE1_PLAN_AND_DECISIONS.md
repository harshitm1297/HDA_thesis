# Phase 1: reproducible import and identifier audit

> Data-only status: the structural milestone is complete and does not wait for new project-group information. Clinical, pathology, batch and governance placeholders remain unknown. External identifier annotation is optional, additive and versioned; it cannot reconstruct the original protein-inference process.

> Current-scope override: `FROM_SCRATCH_DATA_ONLY_ROADMAP_2023.md` now governs execution. No previous analytical result, external cohort, clinical metadata, laboratory metadata or post-2023 research is used in the analysis. The Europe-facing material below is retained as historical planning context only and is not a current deliverable.

## Objective

Phase 1 converts the supplied workbook into reproducible, machine-readable records without changing the source. It establishes the biological sample manifest, gives every feature a stable source-row key, quantifies feature-level observation and paired-detection patterns, and identifies rows that need accession or protein-group review.

The phase is intentionally non-transformative. It establishes whether every specimen and feature can be traced, whether the pairing is valid, which values are missing, and where identifiers are ambiguous before any biological preprocessing is introduced. This ordering prevents a later normalisation, imputation, or annotation choice from being mistaken for a property of the source data.

## Outputs

### Sample manifest

`phase1_outputs/sample_manifest.csv` contains one row per specimen. Patient and tissue status are parsed from the source column name. Original column position is retained so every manifest record can be traced back to the workbook. Clinical and technical fields absent from the supplied files are included with the explicit value `unknown`.

The parser accepts only the declared `P<number>N` or `P<number>T` pattern. It derives pair and tissue fields, checks sample-name uniqueness, and verifies exactly one member of each tissue type per patient. It does not infer anatomy, pathology, chronology, batch, or run order from column position. The resulting table confirms the correlation structure without creating clinical facts.

### Feature identifier audit

`phase1_outputs/feature_identifier_audit.csv` contains one row per workbook feature. It preserves the original identifier and Excel row, assigns a stable row-based feature key, flags duplicates and semicolon-delimited groups, measures observation completeness, and counts paired detection patterns.

Row-based keys are necessary because `PG.Genes` is neither guaranteed unique nor a stable protein accession. For each row, the audit counts measured and missing specimens, tumour and non-tumour detections, complete pairs, discordant pairs, and pairs missing in both tissues. The four paired states must sum to 42. A missing cell is recorded as unreported or unquantified; it is not converted into biological absence.

### Data dictionary

`phase1_outputs/phase1_data_dictionary.csv` defines every generated manifest and audit field. It distinguishes source-derived values, calculated values, and unresolved metadata placeholders.

### Validation report

`phase1_outputs/PHASE1_VALIDATION_REPORT.md` records the input hash, dataset dimensions, pairing checks, identifier issues, missingness, and output hashes. It is regenerated by the import script.

The report demonstrates that the import is internally consistent and repeatable. It does not demonstrate that the upstream mass-spectrometry experiment passed instrument or preparation QC, because those conclusions require the raw files, run order, controls, and acquisition records identified as missing in Phase 0.

### Reproducible script

`scripts/phase1_audit.py` recreates all Phase 1 machine-readable outputs from the immutable workbook.

## Initial rules

The patient is the biological unit. All 84 sample columns must match the pattern `P<number>N` or `P<number>T`, sample names must be unique, and each patient must contribute exactly one sample of each tissue type.

The analytical feature unit remains the original workbook row. Duplicate gene symbols are not averaged, and semicolon-delimited groups are not split. Rows containing no measurements are flagged for exclusion from numerical analysis but remain in the audit record.

Detection means that the source cell contains a numeric value. It does not mean that the protein is biologically absent when the cell is blank. Paired detection counts are descriptive inputs for the later missingness analysis.

The manifest currently uses `unknown` when a value has not been established. Its next version will distinguish `not_applicable` from `withheld`, because a field that does not apply is analytically different from a known value withheld for privacy. Each recovered value should receive a source reference, verification status, and update date rather than silently replacing a placeholder.

## Deferred Europe-facing extension (outside the current scope)

The manifest is structurally correct but is not yet a complete European clinical or EHDS-style metadata record. Its next version should add exact anatomical site and coding system; WHO/IARC pathology entity and edition; clinical and pathological TNM components, stage group and TNM edition; depth of invasion, margins, nodal findings and extranodal extension; specimen distance and pathology; oral potentially malignant disorder; HPV method; geography and recruitment centre; and relevant exposure detail. These are added as governed fields and populated only from verified source records. The [WHO/IARC 2024 classification](https://publications.iarc.who.int/Book-And-Report-Series/Who-Classification-Of-Tumours/Head-And-Neck-Tumours-2024), [EHNS–ESMO–ESTRO guideline](https://www.annalsofoncology.org/article/S0923-7534%2820%2939949-X/fulltext), and [UICC TNM resources](https://www.uicc.org/resources/tnm/publications-resources) define the vocabulary.

A separate governance table should record the data holder or controller, ethics committee and approval, consent scope or other lawful basis, permitted secondary uses, retention, transfer and publication restrictions, access class, and location of any re-identification key. These fields do not belong in a public specimen table if they disclose sensitive institutional information. The structure follows GDPR research safeguards and anticipates the EHDS dataset-description model without claiming that EHDS currently authorises this use. See [GDPR](https://eur-lex.europa.eu/eli/reg/2016/679/oj), [EHDS](https://eur-lex.europa.eu/eli/reg/2025/327/oj), and [Implementing Regulation (EU) 2026/2098](https://eur-lex.europa.eu/eli/reg_impl/2026/2098/oj).

The dataset-catalogue record should describe the purpose, cohort, geography, collection period, specimen relationship, molecular data type, coding systems, quality and utility limitations, linkage potential, formats, access conditions, and responsible contact. It must state that the current matrix is a reduced protein-group/gene-labelled table with incomplete experimental provenance. This lets a future European collaborator judge fitness for purpose before requesting participant-level access.

## Completion criteria

Phase 1 is complete when:

1. All 84 source columns map to 42 complete and unique pairs.
2. Every source feature row appears exactly once in the audit table.
3. All empty, duplicated, and grouped feature identifiers are explicitly flagged.
4. Manifest and audit fields have documented definitions.
5. The script can regenerate identical outputs from the frozen input.
6. Output hashes and validation checks are recorded.

The six criteria above define the completed structural baseline and permit transition to Phase 2. A reviewed `v2` schema, governance limitation statement, EHDS-oriented catalogue description and versioned HGNC/UniProt annotation are optional documentation extensions. Because project-group information will not be obtained, they must preserve unknown values and cannot be treated as recovered clinical or governance facts. Those additions must leave the original audit outputs and hashes unchanged.

## Remaining identifier work

Stable accessions cannot be reconstructed reliably from `PG.Genes` alone. Phase 1 therefore records identifier ambiguity rather than forcing mappings. A later annotation step may add HGNC and UniProt mappings for unambiguous single-gene rows while preserving the original row key. Grouped and duplicated rows will remain unresolved unless stronger evidence is recovered.

The annotation operation will use a frozen mapping release and retrieval date. It will retain original symbol, approved symbol, stable HGNC ID, UniProt accession or candidate accessions, mapping type, ambiguity flag, evidence source, and review note. One-to-many mappings will not be expanded into multiple measured proteins because the abundance remains attached to the original protein-group row. The annotated table will be versioned separately so that updating a database release cannot alter the source audit.

## Evidence supporting Phase 1 decisions

Spectronaut defines `PG.Genes` as a protein-group gene field and allows multiple members within protein groups. This supports preserving the original row instead of splitting a group without accession or peptide evidence: https://biognosys.com/content/uploads/2024/09/Spectronaut-19-manual-v4.pdf

HGNC assigns stable HGNC identifiers to approved human gene symbols and retains previous symbols. This supports adding current nomenclature as annotation while preserving the original source symbol: https://pmc.ncbi.nlm.nih.gov/articles/PMC7494048/ and https://hgnc.genenames.org/help/symbol-report/index.html

The source checksum, stable keys, manifest, data dictionary, and scripted regeneration align with the FAIR principles for scientific data stewardship: https://doi.org/10.1038/sdata.2016.18
